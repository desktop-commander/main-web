The 2 Ways to Tag in Obsidian Markdown

Obsidian supports tags in two distinct locations, and understanding when to use each matters for retrieval.

Inline Tags

Type # followed by your keyword anywhere in a note:

Meeting with design team about the new dashboard. #meeting #design #Q1-planning

Inline tags are contextual—they mark specific sections or ideas within a note.

When you click a tag in Obsidian, you'll see every note containing that tag, making them a quick way to jump between related content. It's also how AI tools navigate your vault—tags give them a reliable way to find relevant content and context across your notes.

Use inline tags when you want to categorize a specific paragraph or thought, not the entire note. For example, you might tag a quote with #quote or a task with #followup while the rest of the note stays untagged.

Property Tags (YAML Frontmatter Tags)

At the top of any Obsidian note, you can add a special section called properties (also known as frontmatter). This is a hidden area—between two --- lines—where you store metadata about the note: title, date, tags, or any custom fields.

Obsidian displays these in a clean Properties panel rather than cluttering your note.

Add tags to the tags property in the frontmatter section at the top of your note:

---
tags:
  - project
  - client-acme
  - active
---

Property tags describe the entire note. They're cleaner for note-level classification and work better with Obsidian's Properties view and Dataview queries.

Many experienced Obsidian users combine both: frontmatter for status and type (#active, #reference), inline for content-specific markers (#quote, #todo).

Nested Tags: building hierarchies in Obsidian

Flat tags work until they don't. When your vault grows past a few hundred notes, you'll want hierarchies.

Create nested tags with forward slashes /:

#project/website-redesign
#project/mobile-app
#client/acme/invoices
#client/acme/contracts

The power of nesting shows in search. Searching tag:#project returns all notes tagged with #project and any subtag beneath it—#project/website-redesign, #project/mobile-app, everything.

In the Tags view panel, nested tags display as collapsible trees, giving you a bird's-eye view of your categorization system.

When nesting makes sense

Good candidates for nesting:

  • Projects with phases (#project/alpha, #project/beta)
  • Clients with document types (#client/acme/contracts)
  • Content types with subtypes (#writing/blog, #writing/newsletter)

Skip nesting when:

  • The hierarchy feels forced
  • You're creating single-use subtags
  • A flat tag with search would work just as well

Tag Syntax Rules for Obsidian

Obsidian's tag reader has specific requirements that trip up new users:

  • Valid characters:
    • Letters (any language)
    • Numbers
    • Underscores (_)
    • Hyphens (-)
    • Forward slashes (/) for nesting
  • Invalid:
    • Spaces (use #kebab-case or #snake_case instead)
    • Pure numbers (#2024 fails, #year-2024 works)
    • Special characters (@, !, etc.)
  • Case sensitivity quirk: Tags are case-insensitive for search (#Meeting and #meeting match), but the Tags view displays whichever casing you used first. If you created #Meeting before #meeting, both display as #Meeting.

This creates a common frustration: inconsistent capitalization scattered across hundreds of notes, all pointing to the same logical tag but looking messy in your tag pane.

Limitations of plugins for tag management in Obsidian

There are plugins available in Obsidian that help manage tags and common issues with them. However, they come with significant limitations.

Tag Wrangler lets you right-click a tag in the Tags view and rename it across your vault. It works, but:

  • Only handles one tag at a time
  • Requires manual identification of problem tags
  • No bulk operations for adding tags to existing notes

Bulk Tag Manager offers more power—case conversion, separator standardization, find-and-replace across the vault. But it still requires you to know exactly what you want to change and operate within its interface.

The fundamental limitation of these tools is to react to problems you've already identified. They don't help you discover inconsistencies, plan a tagging taxonomy, or execute complex reorganizations that require judgment.

Principles for Building a Tag System in Obsidian

Whether you're starting fresh or cleaning up years of organic growth in your Obsidian vault, these principles help:

Start with purpose, not structure

Before creating tags, ask: "How will I search for this later?" Tags exist for retrieval. If you can find a note through search, links, or folder structure, you may not need a tag at all.

Use three tag categories

A practical taxonomy for most users:

  1. Type tags — What kind of note is this? (#meeting, #reference, #idea)
  2. Status tags — What's its current state? (#status/active, #status/archived)
  3. Topic tags — What subject does it cover? (#marketing, #product, #finance)

Resist adding more categories until you've proven these three aren't enough.

Enforce conventions ruthlessly

Pick your standards and stick to them:

  • All lowercase (#project not #Project)
  • Singular forms (#book not #books)
  • One separator style (kebab-case or snake_case, not both)
  • Nested structure for hierarchies

When you inevitably slip, tools like Desktop Commander make bulk corrections painless.

Let AI handle the tedious work

The biggest barrier to tag hygiene isn't knowledge—it's the manual effort of implementation. Checking consistency across hundreds of files, updating legacy tags, adding missing metadata: these tasks are perfect for AI automation. You make the decisions about structure and meaning. The AI handles the filesystem operations.

Frequently Asked Questions about tags in Obsidian Markdown

Can I use emojis in Obsidian tags? ▾

No. Obsidian tags only support letters, numbers, underscores, hyphens, and forward slashes. Emojis will break the tag.

What's the difference between tags and links for organization? ▾

Links create explicit connections between specific notes. Tags add broad categorization. Use links when two notes are directly related; use tags when notes share a category but aren't necessarily connected to each other.

How many tags should a note have? ▾

There's no magic number, but restraint helps. If every note has 10+ tags, your tags lose meaning. Aim for 2-5 tags per note, focusing on what genuinely aids retrieval.

Can Desktop Commander accidentally mess up my vault? ▾

Desktop Commander shows you what it plans to do before executing changes. You can review file modifications and approve or adjust them. For major operations, keeping Obsidian's file recovery or a git backup provides additional safety.

Do tags work with Obsidian Publish and Sync? ▾

Yes. Tags are stored in your markdown files, so they sync and publish like any other content.
